# Hardening requirements

Each requirement below is a property of the v3 model, the module that enforces it, and how a test observes it. They are stated as design requirements.

| #   | Property                                                                                                                                                               | Enforced in                                                            | Observed by                                                                                                                |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | The pusher is resolved from the credential on the connection. Commit author and committer are never used for authorization, permission or the self-approval comparison | `src/identity/resolver.ts`, `src/policy/approval/selfApproval.ts`      | A push with a valid credential and a forged committer line is attributed to the credential's owner                         |
| 2   | The push record id is assigned and opaque. No filesystem path, cache key or lookup key is derived from client-supplied values                                          | `src/domain/push.ts`, `src/git/quarantine.ts`, `src/git/mirror.ts`     | A ref update line carrying path separators is refused at parse time; no directory outside the data root is ever touched    |
| 3   | An approval is bound to repository identity, ref, old id, new id and, in server mode, the pack digest. It is consumed once and expires unconsumed                      | `src/proxy/modes/relay.ts`, `src/store/spi.ts`                         | An approved range pushed to another repository or ref is a new submission that lands in `pending`                          |
| 4   | SSH public-key authentication verifies the signature over the session identifier before the key is looked up. The login name is ignored                                | `src/proxy/transports/ssh.ts`                                          | Presenting a registered public key without its private key is refused                                                      |
| 5   | Request bodies, pkt-lines, pack object counts, inflated sizes and inflate ratios are bounded before allocation                                                         | `src/git/limits.ts`, `src/git/pktline.ts`, `src/git/pack.ts`           | A body under the compressed limit that inflates past the ceiling is refused with a readable error and bounded memory       |
| 6   | A push updates exactly one ref                                                                                                                                         | `src/git/pktline.ts`                                                   | A two-ref push is refused before a record exists                                                                           |
| 7   | Every pack object is reachable from the ref update. Tag objects are inspected themselves                                                                               | `src/policy/checks/reachability.ts`, `src/policy/checks/tagObjects.ts` | A pack carrying an unreferenced commit is rejected; a tag with a blocked message is rejected even when its target is clean |
| 8   | Rejected pushes leave nothing in the mirror                                                                                                                            | `src/git/quarantine.ts`                                                | The mirror's object count is unchanged after a rejection                                                                   |
| 9   | Capabilities that move content around the proxy are not offered; push options are not relayed                                                                          | `src/git/capabilities.ts`                                              | The client-facing advertisement omits `packfile-uris` and `push-options`; a client sending push options is refused         |
| 10  | A check that could not run is recorded as such and defaults to fail-closed                                                                                             | `src/policy/disposition.ts`                                            | With the secrets scanner absent, a push lands in `rejected` or `pending`, never `forwarded`                                |
| 11  | Every mutating API verb is denied unless the authorization matrix permits it. Admin does not imply review                                                              | `src/server/authz.ts`                                                  | A matrix test over every route and verb                                                                                    |
| 12  | Every transition is an audit event with actor type, trigger and time. Every rejection, cancellation and approval carries an attestation                                | `src/domain/lifecycle.ts`, `src/domain/audit.ts`                       | The path of any submission is reconstructable from the event log alone                                                     |
| 13  | Upstream denials are relayed unchanged. The proxy never discloses repository existence the upstream concealed                                                          | `src/proxy/transports/http.ts`                                         | A 404 from the upstream reaches the client as a 404                                                                        |
| 14  | No credential typed by a client is persisted. Forwarding uses the request's own credential or the forwarded agent                                                      | `src/git/forwarder.ts`                                                 | Grep the store for token material after a forwarded push: nothing                                                          |
| 15  | Rate limiting and cooldowns key on the resolved principal and the address                                                                                              | `src/server/app.ts`                                                    | Two principals behind one address are limited independently                                                                |

## Verification plan

- Matrix tests for the grant lattice (every grant pair, implies and overlaps), the lifecycle transition table (every state pair) and the API authorization matrix (every route and verb).
- A parity test asserting the relay and server modes register the same set of checks.
- Container-backed end-to-end tests against a local git server for both modes and both transports.
- Coverage gates per package, highest on `domain`, `policy` and `server/authz`.
